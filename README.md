# dsh-ideas：把记忆和目标变成下一步行动

**中文** | [English](README.en.md)

**结合个人记忆、未完成目标和近期对话，为你准备可以直接开始的下一步。**

## 解决什么问题

聊过的想法、已经制定的计划和真正开始执行之间，往往还差一个具体动作。你可能知道自己想改善什么，却不确定现在最值得做哪一步，也不想每次都重新交代背景。

Ideas 是一个 DeepSeek Harness（DSH）插件。它把个人记忆、Goals 中的未完成步骤和近期对话整理成建议卡片；你选中一张卡片后，可以在聊天里继续推进，并查看实际进度、交付产物和后续跟进。

- **个性化建议**：读取 Meow 记忆与 Goals 的未完成步骤，两种来源交错展示，并保留依据。
- **从建议进入行动**：先查看详情，再点“马上开始”；任务背景交给 Agent，聊天中的开场保持简洁。
- **记录实际进度**：区分正在执行、等待资料、等待审批、等待外部结果、待核验和持续跟踪。
- **完成后更新 Goals**：关联步骤的 Ideas 经核验或用户确认完成后，把完成状态回写到 Goals。
- **后台准备，按需选择**：默认最短每 12 小时准备一批建议；也可以手动生成、调整、忽略或恢复。
- **通用点子**：提供健康、生活、工作等通用入口，不要求先积累个人记忆。

## 安装

前提：已安装 **DSH 0.2.1-alpha.1、0.2.1-alpha.2 或 0.2.1-rc.2 的 Web 版**，并配置好可用的默认模型。Node.js 需要 `^22.19.0` 或 `>=24.0.0`。

1. 打开 DSH 左侧的 **插件 → 添加插件**。
2. 粘贴下面的地址并安装：

```text
https://github.com/dawn0713/dsh-ideas/releases/latest/download/dsh-ideas.tgz
```

3. 启用插件，重启 `dsh web` 并刷新页面。左侧会出现 **Ideas**。0.4.11 起移除聊天右上角的快捷按钮，保留侧边栏入口。

也可以用命令行安装：

```sh
dsh plugin --profile web add "https://github.com/dawn0713/dsh-ideas/releases/latest/download/dsh-ideas.tgz"
```

已下载 tgz 时，直接传入文件路径，无需解压或编译：

```sh
dsh plugin --profile web add "/path/to/dsh-ideas.tgz"
```

源码版 DSH 可在宿主仓库中使用 `pnpm dsh` 替代 `dsh`。更新同名插件后重启即可，保留原有 Ideas 和 Goals 数据。

### 可选配套插件

- **Meow**：提供个人记忆。默认 bundle 使用 `meowMemory` 服务；缺少记忆来源时会显示提示，仍可使用可用的 Goals 来源与通用点子。
- **[Goals](https://github.com/dawn0713/dsh-goals)**：提供跨会话目标与步骤。要使用完成回写，需要安装提供 `personalGoals` 服务及 `get` / `updateTask` 方法的 Goals 插件；已验证与 Goals 0.2.0 功能版本联动。

本仓库发布的是 Ideas 插件，未打包 Meow、Goals 或 DSH 宿主。三个 DSH 版本使用同一个 Ideas tgz，无需切换安装包。

## 怎么使用

1. 打开 **Ideas**，查看“为你推荐”的卡片及其依据。
2. 选择建议，点 **马上开始**，在聊天里继续处理。
3. 到“进行中”查看执行进度，补充资料、调整要求，或暂停与结束跟进。
4. 实际完成后，由产物核验或你的明确确认收尾；同步结果会显示在卡片和详情中。

“采纳”只表示认可建议，不等于已经开始执行；一轮回复结束也不等于目标完成。涉及付款、预订、对外发送或其他具体操作时，仍遵守会话中已有的授权要求。

## 与 Goals 的双向联动

```text
Goals 未完成步骤 → Ideas 建议卡片 → 聊天执行与完成核验
       ↑                                  │
       └──────── 对应步骤标记为已完成 ──────┘
```

Ideas 使用生成时保存的目标和步骤编号回写，不按标题猜测归属。完成反馈先保存到 Ideas，再调用 Goals 的正式服务；同步失败会保留完成记录，显示原因，并提供 **重试同步 Goals**。

已经完成的步骤不会重复写入；已删除或取消的步骤会明确报错。没有关联步骤的记忆建议不会修改 Goals，旧版历史完成记录也不会自动批量回写。完成一个步骤只更新目标进度，**整个目标仍由用户明确确认完成**。

## 首次安装为什么没有推荐

首次启用并重启 DSH 后，后台默认等待约 60 秒再尝试生成；页面打开和“刷新”只读取已经保存的记录，不会立即调用模型。生成还需要可用模型，以及 Meow 记忆或 Goals 未完成步骤中的至少一种真实依据；近期对话只是补充上下文，不能替代这两种来源。两者都没有时，可以先使用“通用点子”。

自动尝试默认至少间隔 12 小时，失败会逐步延长至最多 24 小时。限频和失败状态保存在 `_engine.md`，重启、重新安装或升级不会清除它。想立即检查，可展开页面的“自定义生成”并点“生成 Ideas”；这会实际检索资料并调用模型，也会显示具体错误。“刷新”不会重新生成。

## 数据与模型

- Ideas 默认保存在 `~/.dsh/ideas/`，每条记录是一个 Markdown 文件；后台推荐状态保存在同目录的 `_engine.md`。
- 推荐和执行使用 DSH 已配置的模型，不要求在插件里另存 API Key。
- 生成建议时，检索到的记忆、目标资料和近期对话会作为上下文发送到你配置的模型服务。请按自己的数据要求选择模型。
- 定时跟进使用 DSH 的排程服务，依赖 DSH 保持运行。回合之间不会另建一个独立执行器。
- 停用或卸载插件不会自动删除已经保存的 Ideas 文件。

## 开发

仓库保留了预编译的 `dist/`，安装 Release 的 tgz 不需要运行下面的命令。

```sh
npm install
npm run build
npm test
npm run preview
```

预览地址为 `http://127.0.0.1:3461`，使用示例数据，操作只在内存中生效，不调用真实模型或向真实会话发送任务。

| 路径 | 作用 |
| --- | --- |
| `src/index.ts` | DSH Host 入口、模型调用、服务对接与 RPC |
| `src/client/` | Ideas 卡片、详情、进度与同步状态界面 |
| `src/runtime.ts` | 建议生成、状态更新与任务交接 |
| `src/tracking.ts` | 会话事件、产物核验和后续排程 |
| `src/goal-feedback.ts` | Goals 完成回写、失败记录与重试 |
| `src/store.ts` | Markdown 存储与串行更新 |
| `dist/` | 可直接安装的编译产物 |
| `cordis.patch.yml` | DSH bundle 声明的插件配置 |
| `tests/` | 可移植的行为、RPC 与客户端测试 |

兼容性验证记录见 [docs/VERIFICATION.md](docs/VERIFICATION.md)，维护与发布见 [docs/RELEASING.md](docs/RELEASING.md)。
